## 1 一本の絶対時間枠とslotの入場条件

- **起点 `T0`：** 権限・固定plan・監視／上位保全の利用可能性を確認し、先行責務を空で確保できる設計を前提として、系列の最初の副作用の直前に外側ownerの単調時計で一度だけ採る。保全slot登録、候補内容の読取・hash計算、出力先確保等の系列固有の作業も計上し、build開始やchild readyから数え直さない。`T0` 前は設計と既承認の入力指定の照合までで、準備処理を先行実行しない。
- **絶対締切：** `D_obs = T0 + B_obs`、`D_end = D_obs + R_cleanup`。`B_obs` は通常作業、`R_cleanup` は停止・終了確認・保全・最終判定の専用予約。有限で正の値・単位・加算可能範囲を承認前に確認する。`now >= deadline` は枠外とし、timerの通知が遅れても時刻で判定する。worker時刻／UTCは相関用で、親の単調時刻と直接比較しない。
- **slot入場：** 固定planの次slot、候補pin、同ownerの先行保持、前slotの終端／必要な解除、固定上界 `W_i` を照合する。起動直前の `t_i < D_obs` と `t_i + W_i < D_obs` の両方が必要。`W_i` は設定されたchild timeoutだけでなく、起動手渡し・必要な観測・当該段階のpost-pin・通常終端を含む。残量不足・加算不能・不明なら起動0。slotの絶対締切 `D_i = t_i + W_i` は一度だけ確定し、観測は `min(D_i, D_obs)` より前に終える。既存の個別timeoutで先に停止した場合はそれに従い、外側枠を理由に延長しない。予定より早い完了でも締切を更新せず、次slotは元のplanと残量で再審査する。
- **停止の線形化点：** 想定外の判定・取消・pin不一致・clock不正・観測締切のいずれかを先に確定した時点で、次slot／新規build・pack・試験・対照を同期的に閉じる。早期停止や正常終了でcleanupに先に入っても `D_obs`／`D_end` を更新しない。いつ止まったか不明なら最後の有効時刻と不足理由を残す。外側ownerが必ず期限時に動けるという保証にはせず、独立の保全責務へ渡す。

| ID／観測枠の費目 | 入力・上界の審査単位 | 終了・次段の条件 |
|---|---|---|
| AP5-O01／先行保持・pin | 保全登録、候補commit／tree、検査器・入力manifest、Node実体と承認済み依存、書込み先の空確認。件数、総bytes、走査・hash、登録応答の費用 | 必要なowner／slotと生成前pinを確定。準備失敗は部分生成prefixを保持し、buildしない |
| AP5-O02／build・pack | 空の専用出力での候補build、出力manifest、承認済みpack操作、tarballのhash。入力／出力上限・両コマンド・stdio・pinの費用を別計上 | 出力manifestがpack前、tarball digestが展開前に確定。同じ候補に結合できなければ展開しない |
| AP5-O03／展開・依存準備 | 展開、必要な本番依存と実解決先の固定、展開manifestと検査用fixture添付の分離。展開後の件数／bytes・ローカル依存準備費 | 元の配布payloadが固定され、別dist・ソース／tsx・隣のnode_modules・registryにfallbackしない。依存不足は環境不適合 |

承認票では固定slot数と各上界、slot間の手渡し費を列挙し、系列の観測枠に収まる根拠を結果を見る前に示す。上界未導出は「適合未確認」とし、観測値の平均や過去の最速値で埋めない。現行PK04のコマンド／smoke個別timeout、PK01〜03の一部childに明示timeoutがない事実、AP06の元5秒・既定並列度、旧比較childの60秒、製品期限はこの系列の時間値の代用にしない。

通常のslot退出で必要な子worker・stdioの確認、上位受理、slot専有物の処理は `W_i` に含める。`R_cleanup` は系列全体に一つだけ置き、失敗したslotの残存責務と、どの生成prefixでも残り得る系列共有物の最終回収に充てる。正常slotごとに `R_cleanup` を使い直さず、前slotが未確認なら系列を閉じて予約側へ移る。すでに確認・処理した項目を最終回収で再実行しない。

## 2 cleanup予約：確認の順序と最後の記録枠

`R_cleanup` は下表の `R1〜R7` の合計を下回らない。計画では各費目の有限上界と、`D_obs` を基準にした絶対cutoff（`L_k = D_obs + sum(R1…Rk)`）を開始前に確定する。早期のcleanup着手・既確認項目の省略は可、cutoff後の再試行・余りの配り直し・観測再開は不可。下表は確認期限と責務の順序であり、exit通知の捕捉・stdout／stderr drainを前段の終了まで止める設計ではない。これらの観測は起動直後から並行して続ける。phaseの予定が崩れても最終判定の予約を消費しない。

| ID／予約 | 固定処理・必要な証拠 | 未確認時の固定分岐 |
|---|---|---|
| AP5-C01／R1：停止・初動 | 同attemptを閉鎖し、正常終了または先行理由と停止時点を保持。必要な場合だけ、承認された通常取消・終了要求を同対象へ一度送り、未送信の場合もその根拠を記録 | 要求送信を終端確認にしない。所有不明なら操作しない。強制停止の方式・権限は別承認で、未承認／失敗を自動fallbackしない |
| AP5-C02／R2：runner・子worker退出 | 同attempt／generationのrunner exitと回収、子・孫・threadの正規join／退出、または確認済み未生成を照合（AP5-T01／02） | spawn throw・遅延handle・未登録tail・PIDだけでは不存在を認めない。runnerのcode 0やworker finish返答で埋めない |
| AP5-C03／R3：stdio確認 | stdout／stderrの終端を別確認し、所有stdinは閉鎖、非所有ならその根拠を保持（AP5-T03）。保持量に達しても、承認済みのbounded drainと採取停止を分離 | 欠落・truncatedの結果を完全とみなさない。EOF欠落・errorは別記。保持上限超過を成功文字列で埋めない |
| AP5-C04／R4：post-pin・資源棚卸し | 生成済みのpinを固定照合し、未解放handle・一時領域・候補／混入copy・未受理結果を同slotに結ぶ。照合する件数・byte数・I/Oを限定 | 終端／所有不明で触れない対象は照合未確認のまま保持。別build／共有原本を検索・操作しない |
| AP5-C05／R5：上位受理 | 判定候補と未解決責務を同slotへ一度限り確定し、受理receiptで責務と権限を区別して引き継ぐ（AP5-T04） | 送信だけ・ack不明なら移譲未確認。再発行・削除・次slot起動をしない |
| AP5-C06／R6：固定discard・確認 | 受理後、唯一の処理ownerが、退出・所有・保全が確認された一時領域のみを許可範囲で一度処理し、同slotに結果を記録 | 未終端が参照し得る領域、pin不明・保全未受理は削除しない。部分処理・空確認不足は上位が責務を持つ。外部依存image・元worktreeは対象外 |
| AP5-C07／R7：期限内判定の封印 | 検査結果、AP5-T01〜04の状態、停止理由、残存責務を別fieldで一度だけ確定。R7開始時に不足している確認を待ち直さず、未確認とともに封印する | `D_end` 到達やclock／owner喪失で封印不達なら、先行上位slotから実行未確認として扱う。遅い退出やreceiptで成功へ書き換えない |

数値の根拠は、停止通知上限、追跡できるprocess／thread数と退出観測、stream数・drain／保持量、post-pinの件数／bytes、上位受理・許可された削除・判定記録の費目に分ける。観測不能やI/O無応答を「必ず解放できる時間」に読み替えない。指定時間内に可能なのは、確認できた事実と未確認の責務を、権限を越えずに判定すること。上界・固定観測点・タイムアウト後に残る責務が説明できない費目があれば開始しない。

## 3 終了未確認時の保全と所有の受渡し

| 保持先（論理名） | 着手前に確保するもの | 扱える責務・制約 |
|---|---|---|
| BatchCustody／系列側 | 候補revisionとplan、固定slot、配布物／依存の共有読取範囲、受理待ち欄、監視owner喪失時の問い合わせ先 | slotをまたいで残る候補baseは系列側が所有し、各slotでは借用のみ。全借用の退役・上位受理まで削除不可。未終端があれば次slotを開けない |
| SlotOwner／実行側 | 同slot／attempt／generation、spawn未確認欄、既知resourceの固定台帳、四軸の終端欄、先行理由と末尾未観測欄 | 自分のpartially generated resourceと観測を保持。別slot／別候補のPID・receiptを採用しない。未確認を台帳から消して空に見せない |
| 上位保全先／受理側 | 同候補／slot／attemptの事前に識別された受理枠、終端候補と未解決責務の受領・照会・権限交替契約 | 外側owner／runnerのheapのみに依存しないことが開始条件。場所、方式、アクセス／保持／削除条件、障害時の担当は未承認。ここでパスや機構を選ばない |

受渡しは **同identityで候補値を封印 → 受理側が一度限りcommit → 同一の受理receiptを照合 → 処理権限の所在を確認 → 許可された後始末 → 結果を同slotで封印** の順。候補値は非実行記録であり、権限を含まない。権限の移動点は受理側の同slot commit一箇所とする。ack欠落で送信側がreceiptを確認できない間は、元の責務を未確認の保持として残すが、処理権を取り戻したとみなさない。受理側も自身のcommit・同一性・必要な退出を確認できなければ操作しない。別receipt生成・再送による二重受理・同じ対象への二重削除をしない。上位受理は退出・削除完了の代替ではない。

保全に渡す値は候補・manifest・slot／attempt、PK／対照ID、最後の有効時刻と到達位置、固定の最初の理由、四軸の状態、未解決責務の種別／参照、未採取／切詰めとする。stdout／stderrは固定の要約と状態のみを有限保持し、token・URL・payload・例外本文・環境の生値は保持しない。書込みとreceipt照会にも件数／bytes／回数上限が別途必要。保存先未決・障害で読めない／書けない場合、ローカルheapや通知済みという事実だけを保全成立にしない。

| ID／失敗位置 | 期限内の判定と残す責務 | 後から確認できた場合 |
|---|---|---|
| AP5-U01／spawn開始後にhandle未受領・registry欠落 | 部分生成／所属未確認、既知prefix、一時領域を保持。所有が証明できない対象への停止・削除はしない | 同attemptの証拠が得られたものだけ、別途権限のある担当が回収可否を審査 |
| AP5-U02／runner exit済み・worker／stdio未確認 | 検査結果が得られても終了は未確認。未joinの子と未closeのstreamは別々に保持。関連領域は非削除 | late join／EOFは別記録。元の未確認・timeoutと次slotの閉鎖を遡って解除しない |
| AP5-U03／受理receipt不明・削除失敗／部分実行 | 未移譲または移譲確認不能を保持し、削除完了へ昇格しない。受理済みで削除未確認なら上位に残す | 同receiptや実際の空確認を照合できる場合だけ追記。無条件再送、再削除、元成功への書換えは不可 |
| AP5-U04／clock不正・外側owner喪失・記録不達 | 先行上位slotで当該attemptを調査保留／Unknownとし、最後に確認できた理由と既知prefixだけ残す。時計が無効なら期限内を認定しない | 遅い確認や独立観測は解放記録のみ。両側喪失でも情報が残る方式は未決のため、満たす設計と承認なしでは起動不可 |
