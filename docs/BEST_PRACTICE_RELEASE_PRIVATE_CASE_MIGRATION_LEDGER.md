- **部分対応**：限定した関連assertionがある。表の残差を別途満たす必要があり、旧caseは維持する。
- **未対応**：同条件の移行先証拠なし。関連caseを記す場合も差分参照であって代替ではない。
- **維持**：通常本番経路の元caseを残す。別assemblyへ移した成功件数には加算しない。
- `P`＝本番classをfake I/Oで実行、`D`＝独立開発assembly、`U`＝旧ND単体。いずれも実通信／実認証／正式証拠発行の保証ではない。共有KB／KC／KV-P／KV-Rと、非共有KNの意味は旧表§1を継承する。

### 追加候補の読み方・旧記述の補正

旧表のACK-08〜16等にある「family／C方式の値判断が新assemblyにない」は旧表作成時の範囲を記す履歴である。現HEADにはDC／DA／NRによる固定比較・operator assertion・unknown／conflict／limitationsの試験があるため、上表に追加した。ただしlegacy preparedの拒否、ReleasePermit発行、旧classのprivate結合・公開shapeと同等ではない。特にACK-08〜13／16は開発draftのunknown／mismatched返却を旧停止の代替にしない。旧表の分類自体は変更しない。

SA-26／ND-30の一度takeと、原表FR-01〜06は仕様変更予定の入口試験として残す。FR-01の初回take成功／2回目拒否は将来のexport・登録本体不在検査へ、FR-02〜06のcaller-built fake入力拒否はその入口の撤去／新開発schemaの負対照へ個別に対応付ける必要がある。既存DN-05のHTTP200拒否はFR-05のfake observation schemaと別であり、FR6件をまとめて削除しない。
