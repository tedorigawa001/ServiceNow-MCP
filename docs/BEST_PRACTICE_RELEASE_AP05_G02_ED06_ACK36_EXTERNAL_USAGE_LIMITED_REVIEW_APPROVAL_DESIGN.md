## 3 証拠の受入条件と結論の粒度

証拠は「資料参照／由来・対象版／実解決先の根拠／許可対象箇所／呼出し形／旧結果への依存／影響と引受役割／未確認範囲」に限定する。記録の粒度は次のとおり。資料上の事実、採用仕様からの推論、申告された実運用事象を別欄にする。

| 採否欄 | 受け入れられる根拠 | 限界と記録 |
|---|---|---|
| 指定資料上の該当を確認 | 許可範囲・資料版と照合し、実解決先と旧 `options` 自体の `synthetic_io` 到達、実際の呼出し形／返り値の利用先を追える。同期throwで返り値のhandlerが設定されない等の影響は、見えた例外境界・後始末までに限定 | `synthetic_io: undefined` とキーの省略は区別。資料内の該当であって、利用者数・利用頻度・発生実績は立証しない。回避策の妥当性や互換shimの採用も決めない |
| 指定範囲で該当を観測せず | 承認した資料・箇所を欠落なく読めて、対象入口／転送／返り値依存がその範囲に見つからない。読んだ範囲と何を探したかを添える | 全体の不在ではない。検索ヒット0・報告未着だけでこの判定にしない。複数資料が同じcallerを記述しても別利用者として数えない |
| 未確認／範囲外／判定不能 | 資料未提供、参照途中または隠れた転送、実解決先や版不明、秘匿化で例外境界が見えない、証拠の不一致、上限／停止で未読 | 理由と最後の確認位置を保持し、非該当や影響なしへ補完しない。実運用の申告は資料内での根拠に限り採り、申告の外側をUnknownとする |

この票だけでは外部利用全体のUnknownを解消せず、候補の同期拒否・旧入口不在・通常K02〜04の実bind／解放の証拠を得たことにもしない。旧ACK-36のPromise拒否と案Pの入口拒否、外側async wrapperで見える拒否、[AP04の別結果](BEST_PRACTICE_RELEASE_GUARANTEE_RECOVERY_SCOPE_REVIEW.md)は別の証拠。非提供審査の不足を埋める範囲は、承認された資料で説明できた影響に限る。
