## 2. 今回実装した範囲

[scope-analysis.ts](../src/review/scope-analysis.ts)でASTのスコープを準備してから、
ソース順に受信側の由来を抽象的に追跡する。コード実行や値のevalはしない。

- 関数・ブロック・let/const・varの関数スコープ・引数・catch・for・クラス名・static blockを区別。
  宣言を先に登録し、文字列としてcurrent/previousというだけでプラットフォームの値としない。
- current/previous、直接のフィールド、GlideAjax、既知のローカル値、未解決値を区別する。
  changes系はcurrent/previous由来の直接フィールドに対する呼び出しとして検査する。
- 同じ関数内の単純な別名、オブジェクトの固定プロパティ、配列のリテラル添字、固定プロパティへの
  代入を追跡する。コンテナの単純な共有と再代入も扱う。
- 無条件の再代入は由来を更新する。条件付き代入は可能な由来を保守的に併合し、
  片方の分岐で消えたように見えるだけで候補を抑制しない。ループの固定点計算は行わない。
- getXMLWaitは既知のローカル受信側なら除外するが、受信側が未解決なら候補を残す。
  受信型解析が完全であるとは主張しない。

### BRの標準ラッパーの限定的な入口規則

プログラムが1個のExpressionStatementで、即時実行するFunctionExpressionの引数と仮引数が
厳密にcurrent/previousの2個に対応し、外側で同名が宣言されていない形だけを、
ServiceNowの入口として初期化する。例は標準的なexecuteRuleラッパー。
関数名に依存せず、名前検索・一般の引数伝播・戻り値伝播・呼出し先解決はしない。
別のラッパー形、追加トップレベル文がある形、別名での引数はこの入口規則に含めない。
これは構文テンプレートとして明示した例外であり、一般的な関数間解析の実装ではない。
この入口のcurrent/previous自体を入れ子の関数が直接参照する場合は、字句束縛として保持する。
別名に格納してから別関数で参照する場合の値伝播は行わない。外側での再代入や呼出し順序の
関数間効果は未解決なので、入口の可能性を保守的に残し、実際の到達性・値を確認済みとはしない。

### 限界と上限

関数をまたぐ別名、引数/戻り値、動的なキー、メソッド関数の別名、bind/apply/call、
分割代入のデータフロー、getter、一般の継承/プロトタイプ/ヒープ、with/eval、
グローバル変異の関数間効果はモデル化しない。
分岐は保守的な併合であり、完全な経路感度やループ解析ではない。
関数本体は呼ばれるかに関係なく解析し、未呼出し/if(false)でも一律除外しない。

準備・束縛登録・解析の合計100,000訪問、深さ256を上限とする。
XML・コード容量上限と候補100件の制限も維持し、超過はanalysis_limit/finding_limitで拒否する。
解析中の予期しない失敗はanalysis_failedとして本文なしで返し、legacyへ黙ってフォールバックしない。
限界はbounded_intra_function_analysis / interprocedural_analysis_not_performed /
dynamic_member_analysis_not_performed等で出力する。候補なしを安全性の保証にはしない。

## 5. 再現と履歴の維持

```bash
bdo node --import tsx scripts/bp4-evaluate-v2.ts
bdo node --import tsx scripts/bp4-evaluate-v2.ts --strict
bdo node --import tsx scripts/bp4-evaluate-v2.ts --legacy
bdo npm test -- tests/review
```

既定は新解析。--legacyは明示的な旧bp3-0.1を使い、v0.2初回JSONを再現する。
--strictとの併用も可能で、契約未充足ならexit 2。
v0.1の旧採点器は履歴再現のためlegacyを既定とし、旧評価ケース・採点条件は変更しない。
初回ベースラインのテストもlegacyを明示して残し、新解析は別の再評価スナップショットと比較する。

結果はcandidate/low/info、本文非返却、根拠承認待ちを維持する。
PDIへのアクセス・書き込み・コード実行・npm公開は実施しない。
