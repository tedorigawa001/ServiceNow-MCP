## 1 隔離と固定slot順

- **H／P／Dを分ける。** Hは旧build・旧fixture、Pは同じ候補tarball由来の隔離配布物、Dは開発側の別build・別brand／台帳。実行元・固定entry・実解決先・必要な権限・owner・時間枠・結果を別々に記録する。H／Dの結果・残量・終了記録をPへ流用しない。Pの配布payload、許可ローカル依存、検査用添付、一変異ごとの専有copyを分ける。元worktree・共有依存は削除対象にせず、別dist／ソース／tsx／隣やglobalの依存／registryへfallbackしない。隔離範囲や書込み責務を確定できなければ起動0。
- **系列の先行枠と毎回の照合。** 最初の副作用の前に、承認済みplan・候補指定・隔離範囲・独立観測と上位保全の利用可能性・通常枠と予約を照合する。実際の登録は `T0` 後のSL01内。登録の同枠確認まではbuild以降を起動しない。各起動直前に同候補／系列／owner・段階pin、固定entry／対象・次slotの空き、前slotの所定判定・完全終端、残時間を再照合する。初回SL01の「前slotなし」は固定し、後段の記録欠落とは区別する。slotの飛越し・並行化・再起動・自動再試行はしない。

| 順序 | 次に渡す条件 | 起動0／停止条件 |
|---|---|---|
| SL01 → SL02 → SL03 → SL04 | 先行保全・入力pin → 空buildの出力manifest → 同build由来のtarball digest → 隔離展開payload・実解決先。各段の出口と終端で引継ぎ | 未確定の先行枠、部分生成、必要なpinの欠落・不一致、前slotの終端未確認なら次段起動0。まだ生成していない後段digestは前段に要求しない |

## 2 終了四軸：同slot／attemptの証拠を揃える

候補pin／系列／slot／attemptと該当するowner世代に、起動前の欄から照合する。所定の検査結果、四軸の終了、必要なpost-pinと確定記録は別。外側の同じ単調時計で期限内の証拠受理を確認する。producer側のUTC・発生時刻は相関用で、期限前に発生しても遅着なら期限内受理としない。[固定終了観測点](BEST_PRACTICE_RELEASE_AP05_CANDIDATE_OBSERVATION_COST_LEDGER_DESIGN.md)のV01〜04を根拠にするが、取得手段は選定しない。

| 終了軸 | 必要な確認 | 欠落時に代用しないもの・残す責務 |
|---|---|---|
| AP5-T01／runner・command | 同attemptの生成試行・handle受領、exit／signalと回収。生成しない場合は未呼出し／未生成が確認できた根拠 | spawn throw・handle未着・停止要求・PIDだけで未生成や終了にしない。部分生成／回収不明を残し次slot起動0 |
| AP5-T02／子・worker | 同親／generationの生成受付閉鎖・登録集合の完全性。子・孫とworker threadを区別し、対象ごとのjoin／退出または確認済み未生成 | runnerのcode 0・workerのready／finish返答・空の一覧で、未登録tailや未joinを消さない。次slot起動0 |
| AP5-T03／stdio | stdout／stderrの終端を個別に、所有stdinのcloseまたは非所有の根拠を確認。終端・error・保持打切り・通過量を分け、有界drainは許可範囲で行う | 片側EOF、成功文字列、listener解除・destroy要求で代用しない。物理終端を確認できても必要な判定出力の欠落／切詰めを補えなければ次slot起動0 |

適用外は固定planと所有modeの根拠がある場合だけ。未採取、確認済み未生成、適用外を混ぜない。期限内に所定判定が得られても、当該slotで必要な四軸のどれかが未確認なら次slotを起動しない。正規に系列へ残る共有物の所有と、前slotで終えるべき借用を区別する。

## 3 通常枠とcleanup予約を分ける

`T0` は外側ownerの単調時計で、系列最初の副作用（先行枠登録・候補読取り等）の直前に一度だけ採る。`D_obs = T0 + B_obs`、`D_end = D_obs + R_cleanup`。各起動直前に `t_i < D_obs` と `t_i + W_i < D_obs` の両方が必要。`D_i = t_i + W_i` は一度だけ確定し、当該slotの観測はそれより前。等号・加算不能・時計不明／逆行・残量不足で起動0。個別期限の方が先なら従い、早期終了・取消・再照合でも起点や締切を延長しない。既存の個別timeout、元5秒／既定並列度、別対照の60秒、過去の所要時間はAP05の上界・設定値の代用にしない。

| 費目／確認期限 | 予約の対象 | 閉鎖時の境界 |
|---|---|---|
| `B_obs`／各 `W_i` と手渡し費 | 通常作業、起動・必要観測・post-pin・通常終端／必要な受理と専有物整理。各site・失敗prefixの操作回数・件数・通過／保持bytes・処理／待受を別計上。入場拒否に至る照合費も手渡し費に持つ | 未導出・未承認・時間不足なら次slot起動0。もう消費した試行や確認は帳消しにせず、Rで同じ操作を再計上しない |
| `R_cleanup`／系列に一度 | R1〜R7の合計以上。`L_k = D_obs + sum(R1…Rk)` を事前に確定し、停止時の残存責務・部分生成と系列共有物の最終回収を覆う | 通常枠に貸さず、slotごとに再確保しない。早期cleanup可・確認済みの操作は再実行なし。cutoff後の再試行・再配賦・通常検査再開はなし |
| R1〜R3／AP5-C01〜03 | 同対象への承認済み停止初動、runner／子・worker退出、stdio終端。観測・承認済みdrainは起動後から並行し、Rの順は確認期限 | 所有不明の停止・強制停止への切替は行わない。待受打切りや通知だけを物理終端と扱わない |
| R4〜R6／AP5-C04〜06 | post-pin／棚卸し、同枠の一度限り上位受理、権限が確認された許可対象だけの固定discardと独立空確認 | 未終端／未退役／未受理の対象は削除0。応答不明で再移譲・再削除しない。残存責務だけを次の保全段へ渡す |

[費目・上界設計](BEST_PRACTICE_RELEASE_AP05_CANDIDATE_COST_UPPER_BOUND_DESIGN.md)どおり、正常と到達可能な失敗prefixで配賦を示す。証拠・値・上界・停止／保全の担当が事前に確定しない限り起動0。想定外の結果、取消、pin不一致、時計不正、`D_obs` 到達を確定した時点で新規slotを閉じ、承認済み予約内の終了確認・保全だけに進む。

## 4 終了未確認時の保全責務と最終判定

系列ownerは候補base・共有物と枠全体、slot ownerは同attempt・専有物・観測済みprefixと未確認範囲を持つ。**先行上位枠**は監視側だけの喪失と監視側・runner双方の喪失を区別し、別の承認済み担当が同枠を有限な読み取りで照会できることが必要。登録結果不明なら再登録・buildをせず、保全側まで不通なら、最後に確認できた範囲しか根拠にせずUnknown／調査保留。手元の記録だけで保全成立とせず、代替枠も作らない。[保全方式の選定条件](BEST_PRACTICE_RELEASE_AP05_CUSTODY_SELECTION_CONDITIONS_DESIGN.md)のKS01〜09を継承し、方式・実保全先は選ばない。

| 発生箇所 | 保持する証拠と責務先 | 禁止・起動0 |
|---|---|---|
| 部分生成、runnerだけ終了、stdio片側、post-pin不明 | slot ownerの先行欄に消費済み／未到達／未確認、最後に確定した対象と未解決範囲を別記。該当時は上位枠へ渡す（U01／02、FP02／04／05／07） | 生成済み・未生成を推測しない。使用中の可能性がある領域は削除0。次slot起動0 |
| 受理送信後の応答消失・票の不一致 | 同候補／plan／系列／slot／attempt、世代・封印snapshot・同じ受理commit／票を権威ある同枠で照合。権限交替は受理側の一度限りcommit。照合できなければ送信側は未確認の記録だけ保持（KS04〜06、FP08） | 保全応答なしを非受理とみなさず、許可済みの同枠照会以外は再送・別票生成・権限の取り戻し・削除・次slot起動をしない |
| 削除claim後の途絶・部分処理 | 上位の現在ownerが、退出・所有・借用退役・保全済みの根拠、claim／実操作／独立空確認を分けて保持。後任は許可された同対象の読み取りを引き継ぐ（U03、KS07〜09、FP09） | claimを戻さず再削除0。後から不在を確認しても元操作の成功とはしない。次slot起動0 |
