## 2 機密除外と構造保持の独立した確認

| 確認軸 | 同じ抜粋版について必要な確認 | 不足・不一致の例 |
|---|---|---|
| 機密除外：本文 | 認証情報、個人識別情報・連絡先、テナント識別子・機密URL／パス、リクエスト本文・原ログ、判定に不要な第三者由来の内容を持ち込まない。必要な第三者由来部分の範囲は段階2の権限と一致させる | 伏字の下に元の値が残る、除外範囲が不明、第三者部分が未確認 |
| 機密除外：本文以外 | ファイル名・メタ情報・コメント・変更履歴、埋込み・添付・外部参照、非表示の層を含めて確認する。指定された静的抜粋だけで完結させ、原本・リンク先への遷移を要しない | 表示上だけ隠している、履歴・埋込みの確認がない、原本への遷移が必要 |
| 構造保持：引数と呼出し | `options` 自体のown keyである `synthetic_io` の有無、キーの省略、明示 `undefined`、供給・転送で落ちる箇所、呼出し式の評価位置を区別できる。値を伏せたことをキーや経路の欠如と混同しない | 伏字がキーの削除に見える、転送の前後が混ざる、呼出し位置が不明 |
| 構造保持：返り値・例外・後始末 | 旧Promiseの返却と後段の拒否、返り値のhandlerの設定位置、外側 `try`／`await`・catch／finally・wrapperと後始末の担当箇所を判別できるようにする。入口の同期 `invalid_input` と、外側で見える拒否を混同しない | 例外や後始末の境界が切れ、どちらの経路に属するか判断できない |
| 構造保持：対応・実解決 | 同じ呼出し箇所・利用時点への匿名参照と、同じ旧版・入口の実解決根拠との結合を保つ。型のみ／実行時を区別し、旧版の実解決記録側の抜粋では必要な対応情報を残す | 匿名化で別の箇所・時点が同じに見える、型と実行時の区別や版の対応が失われる |

機密除外は閲覧側へ渡る抜粋全体と付随情報が対象。構造保持は資料種別・指定箇所が担う証拠に照らして確認する。たとえば実解決記録に呼出し本文がないことと、利用側抜粋で必要な例外境界が欠けることは区別する。適用外とする項目には理由が必要で、空欄や一括の「秘匿化済み」を通過扱いしない。機密を除外できても必要な構造が残らない、または構造を残すには機密を出す必要がある場合は、どちらも閲覧0とし、閲覧側で補完しない。
