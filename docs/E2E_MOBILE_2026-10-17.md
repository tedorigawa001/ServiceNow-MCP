## 実機で確認したモデル

| 旧実装の仮定 | 実機での確認・修正 |
| --- | --- |
| `sys_sg_mobile_app_config` にactive/description/branding_color | 実体は `sys_sg_mobile_application`。nameやプラットフォームID等を取得し、架空のactiveフィルターを除去。旧引数は拒否 |
| `sys_sg_mobile_applet` にtable/app_config | 実体は `sys_sg_screen`。name/description/icon/available_offline等。絞り込みは `sys_scope` であり、モバイルアプリとの所属関係ではない |
| `sys_sg_mobile_layout` にname/table/type | 汎用レイアウト表としては使えない。今回の歴史的layout名のツールは `sys_sg_screen_m2m_ui_element` のリンクだけを扱い、`data_kind` で明示 |
| `sys_sg_offline_sync` が設定表 | 表は実在するが、status/action/record/table_name/message等の同期処理状態モデル。旧table/query/max_records設定を書き込む処理を停止 |
| `sys_push_notification` にtitle/body/userを書けば配信 | 実在する表の列はpayload/request_id/push application/platform等。旧入力との不一致を確認し、未検証のキュー作成と `action=sent` を停止 |
| `sys_sg_mobile_session` とactive app定義から利用分析 | 想定セッション表がメタデータに見つからず、検証済みの利用テレメトリー源も未設定。推測のセッション数／active_appsを返す処理を停止 |

`sys_sg_screen_m2m_ui_element.screen` は `sys_sg_screen`、`ui_element` は `sys_sg_ui_element` を参照することを辞書で確認。`sys_sg_applet_launcher` は別のランチャーモデルであり、画面やアプリ定義と一律に置換していない。画面フィールドの正しい名前は `available_offline` で、`offline` ではない。

公式資料: [Mobile screen types](https://www.servicenow.com/docs/r/mobile/sg-mobile-applet.html)、[Create a screen](https://www.servicenow.com/docs/r/mobile/sg-studio-configure-applet-screens.html)、[Mobile translation reference](https://www.servicenow.com/docs/r/washingtondc/mobile/mobile-translation-reference.html)。辞書・rawレコードと照合してモデルを判定した。画面タイプ別の完全な構築とアプリへのナビゲーション設定は別作業。
