# レビュー確認項目の共通語彙（提案版）

Version: bp-followups-0.1。人による意味・付与条件のレビューは未承認。

正本は[src/review/follow-up-catalog.ts](../src/review/follow-up-catalog.ts)。
採点器だけのローカル語彙を製品仕様に昇格させず、まず意味・適用規則・付与文脈・
その項目が証明しないことを共通カタログとして定義する。
これは公式ServiceNow APIの列挙値ではなく、このPoCの追跡確認用語彙。
根拠となる推奨・例外は[Australia台帳](BEST_PRACTICE_REGISTER_AUSTRALIA.md)の該当節を参照する。

## 型と互換性

FOLLOW_UP_CODESは6項目の列挙、FollowUpCodeはそのTypeScript型、followUpCodeSchemaは
Zod列挙型。結果契約モジュールからも型・スキーマを再エクスポートする。
適用規則はisFollowUpApplicableで照合でき、未知の規則は拒否する。

bp-review-0.1のrequired_follow_upは、過去の自然文を含む結果との互換性を維持するため、
今回は自由記述のままにする。既存のJSON Schema・保存結果も変更しない。
この段階では「全既存結果が列挙値だけに制限された」とは主張しない。
将来、結果のコード欄を厳格化する際は、表示用説明とコードを分離するか、結果契約を
別版にして移行する。既存の自由記述を黙って列挙型に置き換えない。

## 語彙

| コード | 適用 | 意味・付与する文脈 |
|---|---|---|
| source_approval | 全規則・汎用 | 根拠がcandidate/未承認の場合に、適用範囲と採用可否の人による確認を求める |
| binding_and_reachability | 全規則・汎用 | 構文候補の変数束縛・受信側・実行経路を解決できていない場合の確認 |
| exceptions_and_business_intent | 全規則・汎用 | 業務意図や例外条件・承認の有無が未確認の場合の確認 |
| workflow_suppression_review | AU-BR-001・文脈固有 | current更新候補と関連し得るsetWorkflow(false)を検出した場合に、抑止理由・必要性・承認範囲・副作用を確認 |
| async_dependency_review | AU-BR-002・文脈固有 | when=asyncと本文のprevious/changes系依存候補を確認した場合に、依存・フォールバック・互換処理を確認 |
| synchronous_ajax_review | AU-CL-004・文脈固有 | Client Scriptの同期GlideAjax候補を検出した場合に、受信側・UI制約・同期の必要性・非同期代替を確認 |

汎用項目だけで文脈固有の項目を満たしたことにはしない。
setWorkflowという語があるだけでworkflow項目を付けない。受信側・更新との順序/分岐の
対応が未解決なら、その制約を併記する。条件欄のchanges系はasync本文と混同しない。
同名メソッドをGlideAjaxと断定しない。具体的項目の付与も違反・経路・例外の確認完了を
意味せず、verification_statusを昇格させない。

inactive_assetは確認項目コードではなくlimitationsの文脈値として別定義する。
レビュー対象版のactive=falseを確認した場合に付け、未知値や別時点の値から推測しない。
非アクティブだからと候補を一律抑制したり、安全性を保証したりしない。

## 実装順序と採点器の位置付け

1. 今回の共通語彙・付与条件をレビューする。
2. 文脈検出と結び付いた出力処理を実装する。字句スコープ/受信側解析が未完ならその限界を明示する。
3. 正例だけでなく同名API・無関係な抑止・条件欄等で項目を誤付与しないテストを実施する。
4. 固定済みv0.2で開発用再評価し、改修に使っていないケースと人の採点で別途検証する。

今回、v0.2の規則固有コードと列挙型は共通カタログ参照へ変更したが、許容集合・採点条件は
変更していない。v0.2の72ケース・保存結果・検出器も変更しない。
F系12件の不足は、現検出器が新しい具体的項目を出さないために生じる出力契約の実装差分であり、
候補検出の取りこぼしではない。語彙の存在だけを理由に全候補へ一括追加して合格させない。

## 回帰検証

- 語彙6項目の完全性、既存汎用3項目の登録、意味/付与条件/限界の存在、規則対応、未知値の拒否。
- 現検出器が汎用項目だけを返すことと、共通化後もv0.2の固定結果が完全一致すること。
- v0.1の結果・既存自由記述との互換性も従来テストで維持する。

これは新規検出器の実装や語彙の採用承認ではない。PDI操作・外部送信は実施しない。
