# 限定的な定数評価：実装・固定再評価・新規検証

Date: 2026-10-17。ruleset bp3-0.4、確認項目カタログbp-followups-0.4。
ローカルPoC。レビュー対象コードの実行・PDIアクセス・外部送信・npm公開なし。

## 1. 対応範囲

[constant-value.ts](../src/review/constant-value.ts)はASTから文字列または真偽値だけを求める。
値を求められない場合は専用のunknown値を返し、JavaScriptとして実行しない。

| 対象 | 制約 |
|---|---|
| リテラル | 文字列・真偽値のみ。数値の一般的な評価はしない |
| const識別子 | 同一関数、単純識別子の宣言、初期化をソース順に確認済み、識別子への書き込みなし |
| 文字列結合 | 両辺が既知文字列の`+`だけ。暗黙変換なし |
| 真偽値式 | 既知真偽値の`!`/`&&`/`||`。短絡側で値が確定する場合は未実行側を評価しない |
| 厳密比較 | 既知の文字列/真偽値の`===`/`!==`だけ。未知値同士を一致とはしない |
| 条件式 | 条件が既知真偽値の場合だけ選択先を評価。未知条件なら両枝同値でもunknown |

API名・固定プロパティ読み書き・オブジェクトの計算済みキー・workflowのfalse判定へ一貫して適用。
配列の数値リテラル添字等、以前からの静的メンバー名対応は維持する。
受信側の由来や規則のwhen判定を省略せず、キーが一致しただけでローカル値をServiceNowの値にしない。
constはTDZ・内側のシャドーイングを区別する。代入/更新/分割代入/for-in/ofの代入先を、
準備済みの字句束縛に照合して無効化する。未呼出し関数内や更新より後の書き込みも保守的に除外する。
他関数でのconst捕捉も今回の値伝播には含めない。with/evalがある関数ではconst識別子の解決を行わない。

let/var、呼び出し（Boolean/String/join等を含む）、プロパティからの値取得、型強制、
数値演算、テンプレート文字列、分割代入・関数間解析は追加しない。
候補の到達可能性を判定するための分岐削除は行わず、if(false)内も候補として残す。
文字列/真偽値以外のホストオブジェクトを変換・呼び出ししない。

## 2. 上限と不確実性

定数式の深さ64、生成/保持する定数文字列1,024文字を上限とし、超過はunknown。
各定数ノードの訪問は既存の100,000訪問予算に加算し、全体超過はanalysis_limitで拒否する。
元のAST深さ256、XML/コード容量、候補100件の上限も維持する。
実行時間やヒープの完全なモデルではない。generalな定数最適化・JavaScriptインタープリターではない。

結果にはbounded_constant_evaluationとdynamic_member_analysis_partialを記録する。
unknownはfalse・既知API名・既知ローカル受信側に変換しない。
未知の計算済みキー・spread・未知キーへの代入を含むコンテナは、プロパティの不確実性を保持して
分岐の合流にも伝播する。キーだけを解決して受信側をローカル扱いにし、Ajax候補を消すことを防ぐ。
この保守的処理は誤候補を残し得るが、実行時の正確なプロパティや上書き順を確認済みとはしない。

workflowの付与条件を「リテラルfalse」から「上記評価で確定したfalse」へ改版した。
同一関数・ソース上の先行関係・workflow_suppression_relation_not_verifiedは維持する。
AU-BR-002/CL-004はrule_intrinsicのまま。項目の有無から例外を識別したとは扱わない。
候補はcandidate/low/info、本文非返却、根拠採用承認待ちを維持する。

## 5. 回帰と追加レビューの経緯

TDDで文字列結合の見逃し、const/真偽値式の確認漏れを失敗として再現してから実装した。
新規境界回帰45件では初期化順、シャドーイング、書き込み、関数境界、eval/with、
型強制を行わないこと、未知値、既知ローカル受信側、キー読み書き、上限、ソース非実行を確認する。
再評価テスト9件では固定結果の再現・改善5+3/退行0・新規ケースの初回結果・CLIを確認する。

独立した5回帰ケースで再現した。原因は未解決の計算済みキー/spread/未知キー代入が
コンテナの由来に残っていなかったこと。新しい経路で不確実性を保持するよう補強した。
systematic-debuggingスキルで再現・原因・修正を分けて確認したもので、18ケースの期待値への調整ではない。
補強後も初回18ケース・固定3セットの保存結果は完全一致。履歴経路の挙動も維持する。
