## 2 提供権限・版固定・秘匿化の事前確認

| 確認 | 個別承認票に必要な根拠 | 不足時の扱い |
|---|---|---|
| 提供元が許可できる範囲 | 提供元の管理者または委任された役割からの確認参照。対象となる抜粋・版・目的・閲覧者範囲・許可期間を特定し、加工した抜粋の提供、閲覧、秘匿化した要約の記録／保持を許す範囲を分ける。委任は対象資料まで確認し、第三者由来部分は提供権限が確認できる範囲に限る | 資料へアクセスできるだけ、リンクを受け取っただけ、口頭の一般許可だけでは通さない。適否を判断するために原本を開かない。権限の不足・失効・取消は閲覧0 |
| 閲覧の個別承認 | 提供権限とは別に、承認者・承認参照・閲覧役割・指定箇所と上限・期限・要約の引受／保全先を記入する。票の参照情報には個人名や原文を転記しない | 提供済みでも閲覧を許可したことにはならない。未記入・曖昧な範囲、閲覧だけ許可され記録が必要なのに記録責務が未承認の場合は開始しない |
| 三種類の版を分ける | ①提供元が特定した元資料版と該当箇所から、②**秘匿化後に実際に閲覧する抜粋版**・対応範囲・加工確認の参照を固定する。③利用側が実解決した旧パッケージ版・entry／moduleは独立の根拠欄とする。版名・日付だけでは②の内容同一性を立証しない | 動くリンクや差替え可能な添付では固定しない。②が更新・再秘匿化されたら別版として再申請。どの欄も候補revision・digestの代わりにしない |
| 秘匿化済み内容の照合 | 提供側の指定役割が、原本管理下で抜粋の由来・対応箇所・除外の概要を確認し、固定した②に結ぶ。②の同一性を示す不変版参照または内容照合の根拠が必要で、方式・数値は未選定。原本を渡したり、原本の照合値だけで抜粋をpinしたりしない | 閲覧者は本文を開く前に最小の承認用メタ情報だけで対象・版・範囲・提供権限を照合する案。内容照合に読取が必要なら、その読取自体が個別承認済みであることを求め、媒体・手段未承認のままプレビューやhash計算を行わない |

照合関係は、**提供権限の範囲 → 承認票の指定箇所 → 同じ秘匿化抜粋版 → 記録できる要約の範囲**。同じ版の証拠と、同じ利用側の実解決先の証拠も別である。承認前に本文を読んで適合性を判断する運用にはしない。提供側確認・閲覧の承認・結果の採否の担当範囲を示すが、人・権限・保全方法は割り当てない。

## 3 秘匿化の合格条件と、意味が失われた場合

| 確認 | 残す境界・除外するもの | 不整合時 |
|---|---|---|
| 機密・個人情報を持ち込まない | 提供側で、認証情報・連絡先／個人を特定する情報・テナント識別子／機密URLや絶対パス・入力本文・原ログを除く。本文だけでなくファイル名、コメント／変更履歴・メタ情報、埋込み／添付・外部参照も対象。見かけ上隠しても表示用の層の下に元の内容が残る形は不可。閲覧用は指定された静的抜粋に限る | 未加工・検証できない形式・原本への遷移が必要なら、提供／閲覧の対象にしない。閲覧者が原本を取り寄せて伏字にし直さない |
| 判定に必要な構造を変えない | `synthetic_io` が `options` 自体にあるか、省略か、明示 `undefined` か、転送で落ちるかを保つ。呼出し式の評価位置、返り値の連鎖、外側 `try`／`await` とcatch／finallyの担当箇所、型のみ／実行時の別、匿名化した同じcaller／版の対応は判別できるようにする。機微な値は残さず、伏字・省略の区別を示す | 伏字でown keyや例外境界、利用版・同箇所の対応が読めなくなったら判定不能。見えない部分を「省略」「後始末なし」「別caller」と推定せず、再提示が必要なら別承認へ。要約を旧コード原文や実行結果として扱わない |
| 持ち出すのは許可された要約だけ | 匿名の資料参照、確認箇所、許された版の参照、確認できた事実・影響推論・未確認範囲を区別する。引用・添付・原本／部分コピー・秘匿化の対応表を許可なく保存・転記・配信しない | 予期しない秘密・本人識別情報、範囲逸脱、版／対象不一致、保持責務の不明、上限・取消を検出したら閲覧と転記を停止。停止理由と未確認範囲だけを権限内で引き継ぎ、無断保存／削除・再開をしない |
