# BP-5 R-2 OL-03 MA-02：信頼元なし時の選択肢・同一端末VMの実施条件

Version: draft-0.1 / Date: 2026-10-24 / Source baseline: `62a2201` / Status: 選択肢の設計のみ。経路/VM/操作/信頼は未選択・未承認

## 1. 回答に基づく出発点

[回答済みチェックリストdraft-0.2](BEST_PRACTICE_BP5_R2_OL03_MA02_USER_INFORMATION_APPROVAL_CHECKLIST.md)のI01〜I05を正本とする。

| 回答 | 現在の前提 | 読み替えてはいけないこと |
|---|---|---|
| I01 既存信頼元なし | 既存検証環境・管理台帳を使う優先案は現時点で利用不可 | 新しく取得する検証器を自動的に信頼する |
| I02 専用環境なし、同じ端末のVMは候補 | VMソフト/guest構成・作成/設定/起動は未定/未承認 | VMが既に存在する、適合性確認済み、操作許可済みとする |
| I03 全能力不明 | 遮断・非共有・監視・強制停止/終了確認は未確認 | VMという名前だけで隔離済みとする |
| I04 独立確認経路なし | 既知の台帳/本人性確認可能な関係者に依存して進めない | 過去の「台帳提示待ち」を現在の計画に残す |
| I05 判断者は本人、記録は非公開local/本人のみ/保持未定 | 役割の担当と記録方針だけが決まった | 特定の鍵/操作の承認、保存path/実権限/保持期限が決まったとする |

**検証器の由来、Rust鍵の独立確認、実行時の隔離は別の条件。VMは後者のリスクを減らすもので、前二者を作らない。** 同じ利用者が操作承認と信頼判断を担当しても、本人の意思だけで未確認のfingerprintや署名が検証済みになるわけではない。

今回の操作はローカル文書の読取・MD更新のみ。5項目Unknown・全体受付無効・telemetry保留、APPROVED_REGISTRY=None・通常v2 Unavailable/gate92・DER/absence停止を維持する。導入・起動・実装・鍵承認/import・archive取得/展開・環境操作・設定変更・実機操作・token/permit発行・担当者への連絡を行わない。完成parts・本番cap・通常strict・Pushにも進めない。

## 2. 信頼元/独立経路がない場合の選択肢

| 案 | 内容 | 追加で必要な判断/証拠 | 現契約で進められる範囲 |
|---|---|---|---|
| O1 保留を継続 | MA-02の実layout認証を止め、不足と条件付きsource導出を保持する | 今すぐの追加操作は不要。再開条件を記録する | 現在の既定。Unmodeled/Unknownを維持し、実鍵抽出・G0完了・archiveへ進めない |
| O2 外部の信頼済み起点を確保 | 組織/第三者の既存検証環境、承認済み配布、認証可能なwitness等を新たに候補化する | 候補の由来・信頼する範囲・独立性・期限。照会/依頼/資料送信は操作別の許可と送信内容承認 | 調査/候補整理まで。現在その起点はなく、確保できると仮定しない。外部の回答も無審査で採用しない |
| O3 信頼bootstrap方針を明示的に見直す | 利用者が既に依拠するOS/管理配布基盤等を起点にできるか、根拠と脅威範囲を審査する | 具体的な基盤/鍵/更新経路の証拠、採用tuple、Rust鍵の確認経路との独立性。既存契約と違う部分の設計レビュー・明示承認 | 設計比較のみ。OS署名/HTTPS/package名だけで現G0を満たしたとしない。新規trust rootの承認は未実施 |
| O4 低保証の探索実験を別枠に分ける | 将来、真正性未確定の入力/検証器を使う探索を必要とする場合、別の実験計画として扱う | 現計画の「信頼済み検証器だけで合成試験」を変更する別設計、強い隔離、明示的なリスク受容と操作許可 | 現在は実施不可。実験成功も候補表示/互換性の観測に留まり、鍵承認・Verified layout・parts/permitへ変換しない |

O3/O4は安全条件をその場で緩めるfallbackではない。リスク受容は「どの保証がないか」の判断で、暗号検証や独立した所有証明を代替しない。同じ配布元の鍵とchecksumを取得するだけ、VM内で複数ソフトが同じ値を返すだけ、新しいGnuPGで自分自身を検証するだけでは不足を解消しない。

**推奨する当面の扱いはO1の継続。** 再開を希望する場合に限り、O2/O3の具体的候補と審査可能性を利用者が選ぶ段階へ進む。O4を標準検証の抜け道にしない。既存情報がない状態で設計書を追加しただけではVerifierUnavailable/TrustUnavailableを解除しない。

## 3. 同じ端末のVMで進めるための条件

以下は製品機能の保証ではなく、未選定のVM候補を評価する必要条件。特定製品の選定・機能確認・設定手順の実行は含めない。候補選定後は、その製品/版・host/guestの公式仕様で可否を再確認し、満たせない項目を省略しない。

| 条件 | 設計上要求すること | 必要な確認/停止条件 |
|---|---|---|
| V01 構成固定 | host OS/CPU、VM基盤の版/由来、guest OS/image/build/CPUを固定。初期macOS arm64試験への適合を別確認 | ホストからguest OS/ABIを推定しない。Linux予備試験だけでmacOS適合を主張しない。候補構成不明なら停止 |
| V02 信頼境界 | host/VM基盤/監視器を信頼する前提と、その由来・権限・更新方針を明示 | 新しいVM内の検証器が自動的に信頼済みにはならない。host侵害・VM escape・基盤欠陥まで防ぐ保証はしない |
| V03 guestからの非共有 | 個人HOME・workspace・鍵ring・credentialsをマウントしない。共有folder/clipboard/drag-and-drop、host filesystem bridge、不要なdevice/USB/agent socket等を無効化/非接続 | 「秘密を使わない予定」だけでは不可。host↔guestの自動連携が説明できなければ停止 |
| V04 通信遮断 | 合成試験中のnetwork adapter/NAT/bridge/host-only等の経路とDNS・proxy・guest agent/IPCを明示し、許可しない通信を外側で拒否 | インターネットだけ切ってhostへ到達できる状態を適合にしない。準備時の取得と試験時のoffline状態を分ける |
| V05 入力持込み | 将来、認証済み検証器closureと合成fixtureだけを固定digest付きread-only媒体等で持ち込む。実鍵/実秘密は使わない | 媒体の作成/接続も別の環境操作。出所未確認binaryをVMだから許可しない。取得と実行の承認を分ける |
| V06 制限された実行 | 非管理者の試験process、固定argv/env、限定scratch、child/agent/helperの起動禁止、資源/共有deadlineを適用 | VM全体の上限と試験processの上限を混同しない。禁止optionを外して起動成功を優先しない |
| V07 監視 | fileアクセス/書込/exec、通信/名前解決/IPCの**試行**と拒否を観測し、GnuPGから変更できない監視記録へ結合 | 「通信が成功しなかった」だけでは無試行の証明にならない。guest内監視なら別権限と改変耐性を審査。監査能力不明は停止 |
| V08 監視の負の対照 | 将来の合成fault sourceで、禁止アクセス・spawn・通信・出力超過を検出できることを先に確認 | 負の対照が見えなければ通常試験の静かなログを安全性の根拠にしない。fault sourceの起動も別途承認 |
| V09 外側停止 | 試験processとは独立した監督からdeadline/取消で停止・終了確認でき、残留process/FDを確認する | VMの画面を閉じることやpauseだけを終了確認にしない。強制電源断はguest内cleanupを証明しない |
| V10 廃棄/復元 | 検証済みbaselineと復元方法、一時領域/仮想disk/snapshot/一時コピーの管理責務を定める | rollbackは外部通信・hostへコピーした情報を取り消さない。消去/復元したことを完全な秘密消去保証へ広げない |
| V11 証拠の取出し | 固定reason/件数/digest等の限定結果だけを、別途許可した一方向/限定経路で検査して保管 | guestログを無審査で共有folder/clipboardへ流さない。動的内容/制御文字/秘密canaryを表示しない |

same-host VMはhostに影響する管理・資源消費を伴い得る。snapshot作成、VM software導入、guest image取得、network/共有設定、monitorの権限付与はそれぞれ変更操作であり、本書では許可しない。専用別端末より独立した管理境界が小さいことを残し、同一端末だけで独立fingerprint確認が成立すると扱わない。

## 4. 準備と試験を混ぜない進行gate

| Gate | 次段階へ進む前提 | 今回の状態 |
|---|---|---|
| D0 方針選択 | O1継続、またはO2/O3の調査範囲/審査方針を利用者が明示。O4は別契約 | 未選択。本書の推奨を選択済みとしない |
| D1 文書上の構成評価 | VM候補/版と公式仕様、V01〜V11の実現方法、残る脅威を説明 | VMソフト/構成未定、未確認 |
| D2 試験用信頼元の成立 | 認証済み検証器/build/依存closureと合成入力/oracleの由来が固定される。Rust鍵の独立確認は別工程 | I01が「なし」のため未成立。VM計画では代替しない。I04の不足も引き続き残る |
| D3 環境操作の個別承認 | 管理者・対象・変更範囲・資源上限・復旧/cleanup・ログ保存先を定める | A欄未承認。VMの作成/起動へ進めない |
| D4 合成隔離試験 | 承認された固定環境と検証器を使い、監視の負の対照・終了確認を含む既存20ケース計画を満たす | 未実装/未実施。VMが起動するだけでは合格ではない |
| D5 実公開鍵の候補抽出 | 合成試験の範囲/限界をレビューし、実入力の再取得/抽出を別途許可する | 未実施/未承認。成功しても鍵信頼承認ではない |

D1の文書評価はD2未成立でも検討できるが、信頼済み検証器を要求する現行合成試験の開始条件を満たしたことにはしない。各gateは自動進行しない。判定不能はUnknown、失敗理由/未到達phaseを残して停止する。

I04のRust鍵の独立確認を合成fixture試験の前提へ循環させない。将来D2〜D4の条件を満たして合成試験を実施できても、それだけではI04・G0・実layoutの信頼条件は解消しない。

## 5. I05の記録方針を実現する条件

検証証拠は「非公開local・本人のみ」という利用者方針に従う。ただし具体的保存path、実効アクセス権/ACL、cloud同期・backup/spotlight等の複製範囲、host/guest双方の一時コピー、暗号化/鍵管理の方針を実施前に確認する。現在それらは未指定/未検査で、完全非公開とは認証しない。第三者の管理者/監視サービスが読める構成なら希望と異なるため、利用者へ確認してから選ぶ。

保持期間は未定のまま。任意の期間や自動削除/永久保存を既定にしない。試験前に保持・廃棄・backup/snapshot・途中失敗時の記録の扱いを決める。公開repo内の設計書は非秘密の方針/集計に留め、実際の監査ログ・個人path/連絡先・実秘密を入れない。

利用者本人が操作承認と鍵信頼判断を担当する方針は維持する。一方、従来設計が別の検証担当/確認者を要求する部分については担当が未指定であり、一人の自己確認を独立レビュー済みとはしない。確認者を確保するか、役割分離を変更する別審査が必要で、今回どちらも選ばない。

## 6. 実行せずに次に決められること

1. O1の保留を続けるか、O2/O3のどちらの具体的候補を検討したいか。既存台帳が「なし」という回答を再提出待ちに戻さない。
2. 同一端末VMを文書上で評価するなら、候補software/host/guest構成とV条件を確認できる範囲。製品推薦・購入・download・導入・設定は別依頼/個別承認。
3. 非公開記録の具体的保存先候補、保持期間、監査/確認者の不足をどう扱うか。方針の回答だけではfolderを作らない。

本書は選択肢の整理まで。O案の採用、VM候補の選定、技術条件の適合確認、実施許可、鍵の信頼承認を記入していない。[操作別チェックリスト](BEST_PRACTICE_BP5_R2_OL03_MA02_USER_INFORMATION_APPROVAL_CHECKLIST.md)のI欄5項目回答済み/E・A・T20項目未チェックを変えず、Unknown・全体受付無効・telemetry保留を維持する。
