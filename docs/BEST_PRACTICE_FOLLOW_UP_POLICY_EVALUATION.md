## 1. 採用した契約

| 規則 | kind | 付与条件 | 評価するもの |
|---|---|---|---|
| AU-BR-001 | context_specific | 同一関数内のcurrent由来のsetWorkflow(false)と更新候補の先行関係 | 文脈の必要/不要の付け分け |
| AU-BR-002 | rule_intrinsic | 非同期本文の当該候補すべて | 検出済み候補への必須項目付与完全性 |
| AU-CL-004 | rule_intrinsic | Client Scriptの当該同期候補すべて | 同上 |

規則固有項目は通常の問題候補にも、防御的/互換処理のある候補にも必要。
previousガード、try/catch、互換分岐を例外識別のヒューリスティックとして使わない。
生成関数は候補検出後に呼ぶ。後者2規則の項目は文脈マーカーの有無に依存せず付与する。
ただし候補がない場合に項目単体を作らず、未知規則・他規則コードを除外する。

候補検出と実際の確認コード列は既存評価内で不変。legacy/scopedの汎用項目のみの
履歴プロファイルも維持する。変更は方針の明確化と評価軸の分離であり、例外分類器の追加ではない。
結果契約bp-review-0.1とコード6種類は維持する。確認項目は例外該当/承認・違反確定の証拠ではない。

## 6. 再現と回帰テスト

```bash
bdo node --import tsx scripts/evaluate-followup-policy.ts
bdo node --import tsx scripts/evaluate-followup-policy.ts --strict
bdo npm test -- tests/review
```

通常exit 0、--strictは境界の不足によりexit 2、引数エラーは固定メッセージでexit 1。
新CLIのカタログ版は0.3。旧CLIは保存JSON0.2の再現に使い、出力を上書きしない。
指標の分離、通常/防御的双方への必須付与、workflow一括付与の誤検出、
候補見逃しを分母から落とさないこと、候補なし分母のnull、旧結果不変をテストする。
確認項目付きであることを根拠にverification_statusやseverityを昇格させない。
